## Schema notes (additions and conventions)

Same fields as `body_*.json`, plus: `needs`, `lab {id,preset}`, `where`, `formula`, `ext [{title,url}]`, `area` (hub id the node belongs to), `hotspot {of,at,label}`, `open_questions` (C2/C3), `steps` (process template, `focus` ids all validated).
- `parents` = hierarchy (hub or physical parent), `parts` = auto-filled inverse of `parents` (hubs list their concept children), `needs` = prerequisite concept graph.
- `where` is the **id of the deepest teardown node** where the concept lives (e.g. `alu_design -> core_alu`, `rectifiers -> rectifier_bridge`). The full path is obtained by walking `hotspot.of` upwards; no concatenated path ids are stored.
- Hotspot coordinates are in the parent frame (metres). Phone frame per the brief (origin centre, +Y up the long edge, +Z out of the screen); PCB/SoC/cluster/core/ALU/adder/NAND/inverter/FinFET frames are local boxes sized to each node `scale_m`; the grid frame is ~100 km wide with +X from plant to outlet. Positions are plausible, not measured.
- Root `electrical_engineering` and 16 hubs (`ee_*`) have `kind: field`. `made_of` of `silicon_channel` = `silicon` (crystal id in crystals.json).
- `kn` links only point to ids in `data/knowledge/nodes.json` (validated).

## Gaps and caveats

- **Textbook refs are sparse by design.** OpenStax has no circuits, electronics, DSP, controls, comms or computer-architecture book, so only math/physics/chemistry/statistics/data-science nodes carry `refs` (all validated against `books.json`). Other nodes carry `ext` links.
- **`ext` URLs were not network-verified**: the sandbox proxy returns 403 for wikipedia.org and ocw.mit.edu. Links are to long-standing Wikipedia article titles and a handful of course/textbook roots (MIT OCW 18.06 and RES.6-007, All About Circuits, Control Tutorials for MATLAB, DSP Guide, Python docs, NumPy docs, KiCad docs). Run `python3 tools/ee_nodes/check_urls.py` from a networked machine and drop any non-200 (candidates for typos: `Hardware_security`, `Hybrid-pi_model`, `Root_locus_analysis`).
- 20 nodes have neither refs nor ext (hubs, a few ICs/analog topics): lead_lag_compensators, drift_diffusion_ee, active_load, multistage_amps, ee_math, ee_physics, ee_programming, ee_circuits, ee_electronics, ee_digital, ee_architecture, ee_signals, ee_dsp, ee_em, ee_devices, ee_control, ee_comm, ee_power, ee_labs, ee_electives
- No OpenStax *Introduction to Python Programming*, *Introduction to Computer Science* or *Principles of Data Science* sections apply to C/embedded/HDL; only `DSC` (ML, time series) is used.
- Prose is original and compact (3 layers per node, 1-3 sentences each); depth varies: circuits/electronics/digital are the most detailed, electives are survey-level. Numeric facts in expert layers are typical values from memory and should get a domain-expert review before publication (especially phone/charger/grid figures).
- Teardown figures describe a generic 2024-class flagship, not a specific model. Hotspot positions are illustrative.
- Syllabus subheadings (e.g. "Fundamentals") are not individually mapped; all bullets under them are.
- The `lab` presets for `signal/logic/control/field/math/network/code` do not exist yet; node data is ready for them. `circuit:three_phase`, `inverter_bridge`, `buck_converter`, `boost_converter`, `flyback_converter` and `device:flash_cell` also need building (listed above).
- Cross-area `needs` only point backwards in track order (checked). Where a natural prerequisite lived in a later area (e.g. sampling theorem for ADCs) a `related` link is used instead.
